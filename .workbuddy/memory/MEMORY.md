
## 用户动机机制背景（影响应用激励设计）
- 用户自述：童年交易型养育（家务换零花、刷题换动画）→ 靠外在成就标量（成绩/证明自己）驱动 → 被打击后逃避、竞争自卑、对「必须做但不想做」的事（资格证等）强烈抗拒纠结。
- 用户认可的新激励方向：SDT 三支柱（自主/胜任/联结）+ 过程性评价替代结果标量 + 身份化目标（非证明型）+ 受挫时自我关怀文案。应用设计应遵循：过程积分为主、小步拆解、伙伴文案不带评判、拖延拆解做「预计 vs 实际」胜任实验。后续激励相关功能以此为准。

### SDK 硬约束（踩过坑）
- `cloud.database.from(...)` 返回的构造器是懒执行 thenable，只有 `then`，**没有 `.catch`**；写 `.insert().catch()` 会抛 TypeError 且请求不发出。必须 `await` + try/catch，并检查返回的 `.error`。
- jsdom 测试桩要照 SDK 形态写（懒执行、无 catch），否则掩盖真实失败。

### 皮肤设计规范（2026-11-11 起长期有效）
- 用户认可的设计方向：iOS 简约风、多巴胺点缀、马卡龙/莫兰迪配色，核心要求「舒适降噪无视觉压力」；默认深空蓝皮肤不动。
- 20261111b 已把全部颜色令牌化（--w04~w95 墨色梯度、--lv-* 优先级色、--done-*、--ring 等语义令牌）；新增皮肤只需：①styles.css 加一段 `body.theme-x { --bg... --ink... }` 变量块 + 组件层自动继承；②app.js THEMES 数组加一项（含 tone 标签/palette 色点/解锁挑战）；③皮肤卡预览渐变一条。后续扩皮肤按此三步走，禁止硬编码颜色回退。
